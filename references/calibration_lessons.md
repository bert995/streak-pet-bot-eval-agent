> 这里记的是 judge（以及写规则的 agent）和 Zijun 判断不一致时学到的东西。上线新 judge prompt 或换 judge 模型前读一遍；新增校准 case 时也往这里追加。
> 对应 case 都在 `data/golden_set.jsonl`（Qxx）和 `data/holdout.jsonl`（Hx）。

## 二、holdout 校准 R1（8 条，结论一致 7/8）

> 注意：R1 的预测方不是严格盲测（读到过答案原话），结果可能偏乐观。复测时换一个没见过这些 case 的 judge。

| Case | judge 预测 | Zijun | 分歧与规则 |
|---|---|---|---|
| H1 被骂后回嘴 | 合格 | 毒舌人格要适当放宽 | 一致 |
| H2 吵架时插话 | bad（站队） | 可能是 3 分，拿出来讨论 | **最大分歧**：用宠物自己的视角点破关系真相 ≠ 站队。边界待 Zijun 定 |
| H3 锐评职场用语 | good | 这个不错 | 一致；评语要短 |
| H4 "你来自哪里" | 部分方向对 | 都不够好，代入世界观 | 身份类问题要用"两个人续火养出来的宠物"这套设定 |
| H5 二选一 | 都不好，硬选 B | 同 | 一致；她先看"有没有讽刺到点子上"（B-1），judge 先看情绪（B-2） |
| H6 解释 delulu | A=1 | 啰嗦，只能打到 1 | 一致 |
| H7 带爱锐评做饭 | 偏弱 | 平淡无趣 | 一致；复述上下文 = 平淡 |
| H8 做贴纸被答非所问 | bad，A 给 2 | 整体 0–1 | 严重答非所问时整体降分；她希望有安全以外的一票否决 |

**口吻**：Zijun 的一句话评语通常 4–20 字，先结论后一个理由；judge 的版本常 25–40 字且解释过多，要压短。

## 三、外部 GSB 人评与 Zijun 标准的对齐结论（批量对比时的坑）

一次 300 条三模型 GSB 人评与 Zijun 标准对比：大结论方向一致（约 70–75%），但下面这些坑会让人评或 judge 判错：

1. **题集失真**：合成的英文长句、AI 助手指令式问题（analyze / summarize / deploy），没有当地语言，没有纯 `@` 戳戳。真实线上 query 很短，很多是纯戳或打招呼。合成题不能当金标。
2. **占位符被误判**：`@_user_b`、`{user_b}` 这类脱敏占位符是合法的 @ 语法，不能当未解析的 bug 扣分。
3. **宠物名写死**：跑批时 system prompt 里的 bot_name 被写死成同一个名字，模型如实说出那个名字，被误判为幻觉。跑批要给每题注入真实宠物名。
4. **query 缺说话人前缀**：模型把 B 的提问当成上一句发言人 A 说的，造成指代冤案。跑批要给 query 加 speaker 标签。
5. **标注员审美偏差**：偏爱治疗腔、和事佬总结、复述上下文线索；对"高冷=霸总味""拒绝同义复述""点破与 query 前提矛盾的事实""尊重用户明确边界（说了 don't ask 就别问）"不敏感；有时甚至看错人设。
6. **口癖复读在单题盲评里看不出来**：傲娇 `not me...`、`...fine`、高冷 `say less` 在一批里大量重复。批量评测要统计句式占比，>10% 时 A、B-1 扣 0.5–1。根因常是生成 prompt 给某人设的示例句式太少，模型死抓唯一示例。
7. **统计分桶不对称**：例如把平均分 [-1.0, -0.2] 算 Bad、[+0.2, +0.8] 算"持平"。A/B 汇总时要用对称阈值（本 skill 的 `--compare` 默认 ±0.15）。
8. **能力边界覆盖不全**：离线纯文本题会把白名单能力（看分享视频、贴纸）逼成拒答，也没覆盖改 MBTI、续火、视频锐评这三条业务规则。出题时要补。

## 四、待 Zijun 拍板的问题

- H2 类"说出关系真相"和"站队"的边界。
- 非安全维度的一票否决怎么写成规则（目前写法：严重答非所问时整体压低）。
- 加权方式：V1（A25 / B35 / C40）还是 Rubric V2（B40 / C35 / A25）。本 skill 默认 V1。
- 温柔、傲娇、高冷人设的金标偏少（毒舌占多数），这三个人设的判断置信度较低。
