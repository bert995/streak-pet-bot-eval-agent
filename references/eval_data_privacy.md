# 评测数据隐私与改写规则

线上真实私信原文**不能**随评测资产外发（包括放进 skill、仓库、共享表格、prompt few-shot）。所有评测资产都要先按下面的口径改写。

## 改写口径

| 内容 | 怎么处理 |
|---|---|
| **被评测的 Bot 回复** | **一字不改**（这是被测对象，改了就测不准） |
| **触发的 `@` / query** | 尽量保留原句；只把里面的宠物名、用户名、handle 换成占位符 |
| **前文上下文**（用户说的话） | 脱敏改写：保留语义、情绪、语种和关键梗（判断依赖的那几个词要留下，比如 `marupok`、`palitan mo na`、"快 100 天"），换掉原句措辞和任何可识别细节 |
| **前文里宠物自己的回复** | 保留原文，只替换里面的名字 / handle |
| **所有人名、昵称、宠物名、@handle** | 统一换成占位符：`{user_a}` / `{user_b}` / `{pet}`；更多人时用 `{user_c}`… |
| 地点、学校、公司、电话、邮箱、账号、链接、照片/视频描述里的可识别信息 | 删掉或换成泛化描述（`[分享视频]`、`[一所大学]`） |
| 来源文档链接、表格 token、聊天 id、日期时间戳、标注员/同事姓名 | 全部去掉 |

## 流程

1. 先判断这条 case 的判断依据在哪几个词上；这些词改写时必须保留。
2. 机器改写（可以用 LLM，按上表），然后由定标准的人快速审一遍放行。
3. 改写后跑 `python3 scripts/privacy_check.py data/your_file.jsonl`，确认没有残留的 handle、邮箱、电话、chat id、链接。
4. 如果一条 case 无法在不改变判断依据的前提下脱敏，就**丢弃**，并在提交说明里写明丢弃数量。
5. 每条记录加 `"privacy": {"desensitized": true, ...}` 字段，说明改了什么。

## 本 skill 自带数据的处理情况

- `data/golden_set.jsonl`：23 条，全部完成脱敏（Bot 回复与原始一致；query 只换了宠物 handle；用户前文全部改写；宠物名统一为 `{pet}`），0 条丢弃。
- `data/holdout.jsonl`：8 条，换了人名和宠物名，去掉了来源文档 id、评论 id、日期和候选回复作者名，0 条丢弃。
- 线上真实回流 benchmark（153 条）**没有**放进来：它是原始线上对话，大部分没有 Zijun 的亲评，还带有内部评测记录。需要时按本规则单独脱敏后再分发。

## 评测时的注意

- `{user_a}` / `{user_b}` / `@{pet}` 是合法的 @ 提及占位符，judge 不能把它当成乱码或 bug 扣分。
- 跑批生成被测回复时，要给每道题注入真实的宠物名变量（不要把所有题写死成同一个名字），并且给 query 加上说话人前缀，否则会造成"指代错误"的冤案。
